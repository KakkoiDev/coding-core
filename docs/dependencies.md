# Locked functional utilities

Lodash 4.18.1 is copied unchanged from its npm archive; registry integrity and
archive SHA-256 are recorded in vendor/LOCK.json. Read vendor/lodash/README.md,
fp/README.md and the source of the exact function when checking an API. Lodash/fp
uses immutable, auto-curried, iteratee-first/data-last operations; array arguments
and callback arity differ from ordinary Lodash. Do not mix their call signatures.

Toolz 1.2.0 is copied unchanged from its pure-Python wheel, verified against PyPI
SHA-256. Original metadata and BSD-3-Clause license are retained. Read
vendor/toolz/toolz/curried/__init__.py, functoolz/itertoolz/dicttoolz source and tests
for local API reference. Python recipes use `pipe` and curried map/filter/unique.
Materialize lazy iterators at the domain boundary to avoid accidental exhaustion.

The Python package exposes the local Toolz path before recipe imports. No pip
installation is required. JS imports the local fp entry directly. A host with an
existing dependency can change those imports to its lockfile-pinned packages.
Do not introduce two independently selected versions in one application.

Keep original licenses when redistributing code. Offline checks hash all retained
source files, excluding Python-generated bytecode caches. Upgrade only by selecting
an explicit release, verifying the archive, replacing the full package, updating
hashes and rerunning behavior tests. No runtime auto-update or CDN is supported.
